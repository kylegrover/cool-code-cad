================================================================================
HOW THE CAD STACK FITS TOGETHER
================================================================================
A CAD product is a stack, not one magic program. Authoring captures intent and a kernel evaluates it into a model. Inspection, interchange, and manufacturing are separate downstream uses of that model—not required steps in one linear pipeline.

--- HOW THIS PIPELINE WORKS ---

  Creation path:
  01 / Author: Describe the thing
  Dimensions, constraints, features, code, or an AI prompt capture what the part is supposed to be.
  Examples: Sketch + dimensions, Code / DSL, Feature history

  02 / Evaluate: Build geometry
  A geometry kernel evaluates booleans, fillets, intersections, topology, tolerances, and measurements.
  Examples: B-Rep · OCCT, Mesh · Manifold, Implicit / SDF · Fidget

  The model: Source of truth
  Authoring intent plus kernel evaluation produce the representation the application works from.
  Inspection and exchange branch independently from here. Manufacturing may use the model—or direct toolpath code may bypass it.

  Independent downstream uses of the model:
  03 / Inspect: Tessellate for display
  The exact model is converted to display triangles. The viewport is the window into the model, not usually the model itself.
  Key distinction: Display triangles ≠ source geometry
  Examples: Viewport, Measurements

  04 / Exchange: Choose what survives
  STEP can preserve analytic surfaces and topology; STL/3MF commonly carry tessellated surfaces. DXF/SVG are primarily used for 2D/vector exchange, though DXF can also contain 3D entities.
  Formats: STEP / B-Rep (Surfaces + topology), STL / 3MF (Tessellated surface)

  05 / Manufacture: When geometry becomes a manufacturing plan
  Slicers and CAM turn geometry into machine motion; direct toolpath systems can generate motion without conventional CAD/CAM.

  Manufacturing routes:
  - 3D printing — Layer-by-layer deposition: Model / mesh -> Slicer -> Toolpath / G-code -> Printer firmware -> Printed part
  - CNC machining — Material removal: Model geometry / STEP -> CAM -> Toolpath / G-code -> Machine controller -> Machined part
  - Programmatic toolpaths — Can bypass a conventional CAD/CAM model: Geometry code -> Path generator -> Toolpath / G-code -> Controller -> Physical output

  Glossary:
  - Modeler / workbench: The editor, UI, feature history, and file workflow a person or agent operates.
  - Geometry kernel: The math engine that creates and modifies shapes; OCCT is the common open B-Rep example.
  - B-Rep: Surface geometry plus the edges and vertices that bound it. Common in mechanical CAD, STEP exchange, filleting, and machining.
  - Mesh: Triangles approximating a surface. Excellent for display and printing; lossy as editable CAD.
  - Slicer / CAM: Manufacturing planners: a slicer makes additive layers; CAM makes subtractive cutting paths.
  - G-code: A family of controller-specific instruction dialects for moves, speeds, temperatures, spindle state, and other machine commands.

  The important boundary: a viewer can make an STL and a B-Rep STEP file look equally smooth, but the STEP model can retain that a round wall is a cylinder while the STL stores triangles. Rendering quality and geometry quality are separate concerns.


================================================================================
CODE-FIRST CAD
================================================================================
Design 3D models by writing code instead of clicking in a GUI. Parametric, reproducible, version-controllable. See also the curated-code-cad (https://github.com/Irev-Dev/curated-code-cad) list.

--- B-Rep / Solid Modeling ---
Boundary Representation is the dominant approach in mechanical CAD. These tools build geometry from faces, edges, and vertices — many backed by the Open CASCADE Technology (OCCT) kernel.

See also awesome-cadquery (https://github.com/CadQuery/awesome-cadquery).

PROGRAMMATIC G-CODE
================================================================================
Use code to generate, parse, inspect, or transform machine instructions. Direct generation enables parametric paths and unusual fabrication strategies, but output must match the target controller's G-code dialect and machine limits.

--- Agent-Ready CAD Loops ---
The useful pattern is not merely text-to-mesh: keep editable source, give the agent a real geometry engine, and close the loop with renders, measurements, validation, and exact export. MCP can expose that loop, but a browser or CLI an agent can operate may be enough.

  Tags: browser, brep, opencascade, javascript, ai, agent-api, source-available
  Feature-rich browser workbench forked from CascadeStudio: OCCT 8 B-Rep, Monaco, in-viewport constrained sketching that emits readable JavaScript, live parameters, feature commands, code↔geometry linking, and a Playwright-friendly `window.CascadeAPI`. License caveat: upstream remains MIT, while ChiselCAD's additions are source-available and prohibit selling, repackaging, or embedding the editor commercially without permission.
